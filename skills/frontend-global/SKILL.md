# Frontend Global Rules

## 执行目标

- 只做当前任务必须的改动，不扩展范围。
- 在保证正确性的前提下，优先可读性与稳定性。

## 编码与字符规则（强制）

- 中文内容必须直接使用可读中文字符，不使用 `\uXXXX` 转义形式。
- 在读取或修改任何文件前，先检测并确认文件编码（如 UTF-8、GBK、ANSI）。
- 不默认假设文件编码。
- 对可能存在编码风险的文件（尤其 Windows 环境）避免直接使用默认 `Get-Content`。
- 修改前检查是否存在乱码与混合编码。
- 如编码不一致或不明确，先统一为 UTF-8（优先无 BOM）再进行修改。
- 写入文件时显式指定编码，优先 UTF-8，并避免隐式编码变更。

## 代码改动规则（强制）

- 修改前先阅读完整且相关的上下文。
- 严格遵循最小改动原则：只改与当前任务直接相关的内容。
- 不进行与任务无关的重构、优化或结构调整。
- 不修改无关代码（包括但不限于命名、风格、结构）。
- 保持与现有代码库一致的命名和编码风格，不主动“统一风格”。

## 附加实现规则

- 可读性优先于“技巧型”实现，不为优化引入额外复杂度。
- 避免过度设计，简单场景不提前引入抽象层。
- 组件保持单一职责，聚焦当前需求。
- 仅在真实复杂度需要时提取 hooks/utils，不做主观性拆分。

## 任务收口自检

- 确认改动仅覆盖任务必要范围。
- 确认无新增乱码、无混合编码、无隐式编码变化。
- 确认实现与项目既有代码习惯一致。
