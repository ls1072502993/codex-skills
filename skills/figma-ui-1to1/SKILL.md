# Figma UI 1:1 规范

## 概述

将 Figma 设计稿作为唯一事实来源。产出应是可开发的页面，具备真实 DOM、真实素材，并尽量减少与设计稿的视觉偏差。只要设计稿已经定义了视觉结构，就不要擅自改写实现方式。

这是 Figma 高还原实现约束，不替代通用前端 skill；其他通用执行习惯继续遵循 `frontend-global`，同时按任务叠加 `generate-ui`、`vue`、`css` 等专项 skill。

## 核心规则

- 编码前先读 Figma 结构，确认模块划分、节点层级、填充、描边、圆角、透明度、效果，以及某个视觉是否适合直接导出。
- 用真实 DOM 承担结构、文本、语义、链接和交互区域。
- 只要 Figma 已经提供了可直接使用的视觉素材，就优先使用真实导出素材；除非用户明确要求代码原生重建，否则不要用 CSS 重绘已有设计素材。
- 保持最小改动，只处理设计还原本身，不顺手重构无关部分。
- 如果用户要求新起一版，就新建文件，不要复活已经删除或废弃的旧版本。

## 布局规则

- 如果设计稿包含栅格，就以栅格作为内容宽度、对齐方式和间距节奏的依据。
- 内容区宽度应跟随栅格定义，不要硬编码一个猜测值。
- 如果设计稿中的背景层、氛围层或装饰溢出突破了内容栅格，代码里也要按同样方式向外扩展。
- 区块高度和纵向节奏应跟随设计稿，不要套用通用落地页的默认留白。

## 素材取舍规则

- 在拆小图层重建之前，先确认复杂视觉是否已经在 Figma 中存在完整合成节点或分组。
- 当设计稿使用完整手机图、徽章、品牌锁定稿或其他固定视觉样式时，优先导出单个完整合成素材。
- 如果某个视觉在设计稿里本质上是“完整合成图 + 局部装饰”的锁定关系，就不要把它拆成多个独立图片后再手工拼回去；只要拆分后无法 1:1 复现原始蒙版、透视、旋转和遮挡关系，就回退为导出完整合成素材。
- 如果设计稿节点是“图片填充 + 节点级描边 / 圆角 / 效果”，代码里要一并保留这些节点属性；不要默认导出的图片填充已经包含这些视觉。
- 如果最终使用的是局部拆分素材而不是完整合成图，必须逐项核对该素材在 Figma 中的缩放方式、裁切区域、蒙版关系、旋转角度、混合模式和透明度；缺任一项都不能直接落代码。
- 如果视觉锁定关系比文本可编辑性更重要，就优先使用导出切图，而不是手动重写文本排版。

## 背景规则

- 不要用 `<img>` 去定位整屏或整区块的背景图，背景视觉应通过 CSS `background` 实现。
- 在用渐变或特效重建多层背景之前，先检查 Figma 里是否已经存在合成完成或可直接导出的背景节点。
- 只要真实设计素材存在，就不要用猜测出来的纯色、渐变或程序化效果去替代设计稿背景。
- 如果背景有多层，先判断哪些层应该保留为代码可编辑层，哪些层应该直接导出为背景素材。
- 不要把“背景原始素材”直接当成“最终区块背景”去 `cover` 或拉伸铺满；先确认它在 Figma 里是否经过了旋转、蒙版、裁切、混合模式或额外叠层处理。
- 如果导出的是纵向素材、局部氛围层或被旋转后的纹理层，代码里必须保留对应的长宽比、定位、旋转和遮罩逻辑；不能因为方便就改成整块 `background-size: cover`。
- 只有在确认设计稿本身就是代码渐变 / 纯色 / 程序化效果时，才能自行用 CSS 重建；否则不要在真实背景素材上额外叠加未经设计定义的渐变、模糊感或染色层。

## 文本与透明度规则

- 在微调样式数值之前，先保留设计稿中的文字层级、换行和对齐关系。
- 如果正文、辅助文案或说明文字在设计稿中使用了透明度，代码里也要按对应透明度或带 alpha 的颜色实现同样的视觉效果。
- 不要因为 DOM 文本可编辑，就把原本半透明的辅助文案强行改成不透明。
- 如果文字标识或品牌文案换行本身属于固定视觉锁定关系，就应保留该锁定关系，而不是随意重排。

## 定位规则

- 优先使用正常文档流、`flex`、`grid`，以及等价的 auto-layout 思路实现布局。
- 只有当设计稿确实依赖叠压、钉住、悬浮装饰或画布式摆放时，才使用绝对定位。
- 只要一个布局可以不用绝对定位实现，就不要用绝对定位。
- 当必须使用绝对定位时，只让它服务于局部确实需要的视觉，不要用它去搭整页骨架。

## 实现流程

1. 编码前先检查目标节点树，以及所有栅格或布局辅助线。
2. 先判断哪些视觉应该直接导出，哪些应该保留为代码原生实现。
3. 在写样式前，先导出整屏背景、整区块背景和完整合成视觉。
4. 页面结构先搭成全宽区块外层，再根据设计栅格生成内部内容容器。
5. 背景图统一通过 CSS `background` 实现。
6. 把导出图里未必自带的节点属性补回代码中，例如描边、圆角、透明度和阴影。
7. 对于 Hero、整屏插画、手机合成图、区块氛围背景等复杂视觉，先做“完整导出优先”判断，再决定是否允许拆图实现。
8. 如果使用了导出素材，先记录它对应的 Figma 节点尺寸与摆放方式，再写 CSS；不要离开原始节点尺寸凭感觉写 `cover`、百分比缩放或额外渐变。
9. 对照 Figma 截图逐段检查，而不是不加判断地整体重画页面。

## 检查清单

- 检查内容宽度、间距和对齐是否遵循设计栅格。
- 检查所有适合直接用图的视觉，是否被擅自替换成了 CSS 绘制。
- 检查整屏背景和区块背景在可导出时，是否使用了真实背景素材。
- 检查导出的背景素材是否沿用了设计稿中的原始比例、旋转、蒙版、混合模式和透明度，而不是被 `cover`、拉伸或二次染色。
- 检查 Hero 手机、整机合成图、品牌装饰和区块主视觉，是否被错误拆分成多个独立元素后重新拼装。
- 检查图片填充卡片是否仍保留原始描边、圆角和效果。
- 检查透明文字处理是否仍然符合设计稿。
- 检查绝对定位是否只出现在设计确实需要的位置。
