# codex-skills

这个仓库用于集中管理我在 Codex 中使用的本地 Skills，目标是把常用开发约束和执行流程沉淀成可复用规则。

## codex个性化配置 设置 => 个性化 => 自定义指令

- 处理任何任务前，必须先判断命中的 skill，并读取对应 skill 内容。
- 只要任务涉及某个 skill 的适用场景，就必须遵循该 skill；不得因改动小、只读文件、只回答问题或只执行命令而跳过。
- 在未读取并确认相关 skill 约束前，不得开始分析、修改代码、运行命令或给出执行结论。
- 多个 skill 同时命中时，相关 skill 规则全部生效；如规则冲突，优先执行与当前改动最直接相关的 skill。


## 仓库用处

- 统一管理前端开发中的核心规则（编码、最小改动、接口消费、样式、注释、提交规范等）
- 在不同项目间复用同一套技能约束，减少重复沟通与重复配置
- 让 AI 协作输出更稳定，减少“风格漂移”和无关重构
- 基于 Git 历史追踪每次 skill 的演进

## Skills 目录说明

每个 skill 目录通常包含：

- `SKILL.md`：skill 说明、适用场景、强制规则、执行提醒
- `agents/openai.yaml`：agent 侧配置

当前已包含：

- `api`：接口请求与返回值消费规则，强调以后端返回字段为准，不加兼容层和二次格式化
- `comment`：代码注释规则，要求改动时同步补齐必要注释并按模块组织
- `css`：SCSS 编写规则，强调合法嵌套、层级一致与最小样式改动
- `figma-ui-1to1`：Figma 页面高还原实现规则，强调以设计稿为唯一事实来源，优先使用真实导出素材，尤其要求复杂主视觉与背景优先保留完整合成关系，避免错误拆图、`cover` 拉伸和脱离原节点关系的重建
- `frontend-global`：仓库级全局规则，适用于任意文件改动，包含编码检查、最小改动、禁止无关重构等硬约束
- `generate-ui`：UI 生成规则，适用于页面、组件和静态界面开发，强调直接交付代码且默认不启动本地预览、不用内置浏览器验排版
- `git`：提交信息与提交流程规则，基于 Conventional Commits 并结合仓库本地约束
- `uniapp`：uni-app 开发与小程序发行上传相关流程规则
- `vue`：Vue 3 + TypeScript 组件开发规则，强调 `.vue` 文件按 `template`、`script`、`style` 排序、响应式简化、DOM 模板引用优先使用 `useTemplateRef`、适合 `defineModel` 的双向绑定不要退回到 `update:key` 交互方式，以及局部最小改动

## 使用方式

1. 将本仓库同步到你的技能目录（或作为统一规则源）。
2. 在执行任务前匹配命中 skill。
3. 按目标 skill 的 `SKILL.md` 约束执行改动。
4. 如有多个 skill 同时命中，按任务上下文组合执行。

## 维护约定

- 新增 skill 时，补齐对应的 `SKILL.md` 与 `agents/openai.yaml`
- 修改 `skills/*` 内容时，同步更新 `README.md` 中对应 skill 介绍
- 具体同步要求见仓库根目录 `AGENTS.md`
